# Карта кода оригинала (по декомпиляции CFR)

Имена классов обфусцированы. Здесь только то, что **проверено по коду**; всё остальное помечено «не разобрано».

## Точка входа и цикл
- `Main.GOF2MIDlet` — MIDlet, создаёт канвас `Main.n` и поток; состояния RUNNING/RESUME/PAUSE.
- `Main.n` — GameCanvas: цикл кадра, ввод, пауза. Ввод разобран и портирован в `src/input.ts`.

## Ввод (`Main/n.java`) — портирован
Битовая маска, рёбра нажатия/отпускания за кадр. Таблица клавиш — в `src/input.ts` (`KEY`, `TABLE`).

## Данные — портированы в JSON
`bl.java` (все `.bin`), `dn.java` (`ru.lang`). Формат DataInputStream, проверен «до конца файла».
`dn.java` содержит ещё таблицы индексов строк (`dn.a … dn.i`) — смысл не разобран.

## Движок (собственная фиксированная точка) — частично
- `k.java` — тригонометрия: таблица синуса на 1024 шага, **4096 = 1.0, угол 4096 = круг**. См. `src/fixed.ts`.
- `ba.java` / `ag.java` — камера: `ba.a(width, height, fov, near, far)`; FOV = `fov * 0.087890625°`.
  Пресеты камер из кода — в `CAMERA_PRESETS` (основная сцена `Main/o.java:120`: fov 750 ≈ 65.9°, near 500, far 32000).
- Рендер: M3G `Graphics3D` (`dr.java`), меши собираются вручную из VertexArray/VertexBuffer
  (`ai.java`, `am.java`, `b.java`) — **не** через `Loader.load` сцены. Поэтому в `.m3g` нет камер/света/анимации.
- Просмотр корабля (`Main/b.java:225`): камера `(0, 400, -df.a[id])`, поворот `(256, 2048, 0)` —
  таблицы `df.a/df.b` перенесены в `SHIP_VIEW_DIST/OFFSET`.

## Сущности и ИИ — частично (декомпиляция с `--renamedupmembers true`, иначе поля неразличимы)
- `w.java` — абстрактная сущность сцены: состояние (1 бой, 3 взрыв, 4 обломки, 5 переход, 6 варп-выход), фракция (`var_int_d`; в коде встречаются 0–3, 8, 9),
  содержимое для дропа (пары «id предмета, количество»; при уничтожении случайная часть уходит в трюм игрока), модель.
- Наследники `w`: `cb` (корабль с ИИ, 692 строки), `av`, `dm`, `do`, `dh` (статичная точка), `ac`.
- `cb.a(long dt)` — покадровый ИИ корабля. Портировано в `src/ai.ts`; каждое правило помечено **[КОД]** или **[ДОГАДКА]**:
  переоценка цели каждые 5 с (30% смена), дальность обнаружения 50000, скорость/поворот по умолчанию 2.0, «паника» после потери >40% корпуса
  (скорость 3.0, поворот 1.3 на 5–8 с), стрельба при ошибке наведения <0.05, дальность стрельбы 35000, обломки 45 с.
- Декомпилятор в этом методе путает типы переменных. Единицы поворота (`dt*turn`) я истолковал как угловую скорость — это **догадка**.
  Урон и период выстрелов в коде зависят от оружия, в `ai.ts` стоят подстановки.
- `br.java` — **группа снарядов (залп)**, не построение кораблей (в прошлой версии этого файла я это ошибочно назвал построением).
  Статическая таблица — раскладка точек вылета N снарядов (1–10) на носу корабля → `public/data/volley_layouts.json`.
  Там же урон по площади: `damage * (радиус − дистанция) / радиус`, урон берётся из атрибута 10 предмета.
- `ed.java` — сцена/сектор: создаёт сущности (много `Random`). Подробно не разобран.

## Корабль игрока и оборудование — разобрано, портировано в `src/player.ts`
Источники: `dq.a(int, cq, ae, ay, int)`, `df.void_d()`, `ak.java`, `ad.java`. Проверено 30 тестами (`npm test`).
- Крейсерская скорость **2 raw/мс** (≈0,49 ед/с); у врагов по умолчанию те же 2,0.
- Поворот за кадр = `манёвренность × ввод × dt / 3` единиц угла (≈ 29°/с × манёвренность). Манёвренность = `ships.bin[8]/100` + `бонус двигателя/100`.
  Поле, которое я раньше называл `scale` в `ships.json`, — это и есть манёвренность.
- Крен ±384 ед. угла (33,75°): растёт на `манёвренность × dt`, без ввода затухает на `dt/2` за мс.
- Форсаж (предмет категории 14): скорость `2 + trunc(бонус%/100 × 2)` (атрибут 23), длительность — атрибут 25, перезарядка — атрибут 24 (таймер уходит в минус и растёт до нуля, затем сообщение «Ускоритель готов»).
- Щит (категория 9): ёмкость — атрибут 16, **полная зарядка за атрибут 17 мс** (каждые 100 мс + ёмкость/(мс/100)). Броня (категория 10) — атрибут 18.
  Максимум HP (`df.int_e`) = корпус + щит + броня. Двигатель — категория 16 (атрибут 26 = +% манёвренности), расширение трюма — 12 (атрибут 20).
- Названия предметов: `ru.lang[569 + id предмета]`.
- Оружие (категории 0–3 и 8). Вызов в `ed.java:196` передаёт в пул снарядов `br`: атрибут 9 → урон (`ak.b`), **12 → время жизни снаряда, мс**, **13 → скорость, raw/мс**
  (подтверждено кодом `br`: TTL уменьшается на dt, смещение за кадр = скорость × dt; скорость корабля к снаряду не добавляется).
  Атрибут 11 (`br.d`) — **не найдено, где используется**; в `player.ts` он остаётся догадкой «интервал выстрелов». Атрибут 10 — урон по «системам» (ЕМР) через `ak.a`; в песочнице не реализован.
- Граница сектора: при |координате| > 500000 корабль возвращается в (20000, y, 20000).
- Урон `ak.b(dmg)` — **подтверждено**: щит → броня → корпус; щит перед вычитанием усекается до int (`combat.applyDamage`).
- Ремонтный робот (категория 15, «Робот-помощник»): корпус +1 каждые 600 мс, броня +1 каждые 1000 мс. Щит от него не зависит (нужно время зарядки > 0).
- Попадание снаряда (`br.a(long)`): по каждой оси `|цель − снаряд + смещение_за_кадр| < радиус цели` (куб, не шар) — `combat.boxHit`.
- Урон по площади (`br.b()`): `(радиус − расстояние)/радиус`, для целей с `boolean_a` ×0,6. Не включён в песочницу (нужны ракеты).
- **Раскладка полёта** — найдена не в коде, а в справке игры (`ru.lang[22]`): 5 — огонь/выбор, 9 — автопилот, 7 — авто-огонь, 3 — ускоритель, 0 — вид назад/турель, правый софт — меню действий. Применена в песочнице.
- **Не найдено:** где используется атрибут 11; радиусы столкновения реальных кораблей (в песочнице — по размеру модели). Автопилот (9) и турель не реализованы.

## Миссии — разобрано, портировано в `src/missions.ts` (28 проверок)
- `ed.java` (метод настройки миссии, `switch` по типу контракта `dj.int_d()`) создаёт сущности; `cl.java` проверяет условия победы/поражения (26 типов условий, все перенесены в `check()`).
- Сложность `dj.i()` (0–10) задаёт размер группы: `база + (int)(k × сложность/10)`; типы 1, 2, 3/5, 4, 6, 7, 9, 10, 11, 12 (тип 8 в генераторе отсутствует).
- Типы по поведению: 1 — группа врагов; 2 — защитить союзников; 3/5 — сопровождение (последний корабль — подопечный); 4 — пираты; 6 — одна усиленная цель; 7 — расчистить астероиды за 121 с;
  9 — защитить 5 объектов; 10 — уничтожить охраняемые объекты; 11 — пустой сектор; 12 — **соревнование с напарником** (победа, если все убиты и у игрока убийств больше).
- Счётчики `ed.var_int_c` (убийства игрока) и `ed.var_int_b` (чужие) растут в `ed.a(bool)`; `ed.int_b()` — оставшиеся враги.
- Названий типов миссий в `ru.lang` я не нашёл (таблицы `dn.b/c` — это обучающие подсказки), поэтому `kind` описывает поведение, а не официальный текст.
- Типы 0 и 11 в `ed.java` не имеют ветки с сущностями: это перелёты/доставки до станции (генератор требует назначение не в текущей станции).
- Не разобрано: диалоги миссий, сюжетные миссии (`cf.java`, строки ~314–543).

## Контракты, награды, ранг — разобрано, портировано в `src/contracts.ts` (19 проверок)
- `dj.java` — только контейнер (тип, текст, фракция, награда, станция назначения, сложность). Генератор — `bx.a(cy)`.
- **Ранг игрока** (`cf.m()` = E): стартует с 1, порог 15; очки = `убийства + t/2 + руда/50 + редкие находки + 2·контракты`; ранг +1, когда очки > порог × 1,3 (порог становится равным очкам), не больше +1 за вызов.
- **Тип контракта:** случайный из 0–12 без 8; до сюжетного шага 16 — только 11, 0, 7, 4, 12. Роль агента 5 → доставка (тип 8, назначение — станция агента). Тип 12 — назначение у агента.
- **Сложность:** 1–2 до шага 16, иначе 1–9; не выше 10. Размеры: тип 3/5 — `2 + (int)(8·сл/10)` кораблей; тип 0 — `5 + (int)(95·сл/10)`; тип 11 — `2 + (int)(18·сл/10)`; тип 2 — `2 + rnd(4)`; тип 8 — 5–19 штук предмета.
- **Награда:** `(1500 + (int)(сл/10·5500)) × (1 + расстояние/1200) + ранг·200`; тип 7 ×0,7; тип 9 ×1,2; типы 3 и 5 ×2; тип 11 — ×0,6 и + количество·(f/5); тип 8 — `f/2 + кол-во·цена·3`. Округление до кратного 50 (ровно +25 — вверх).
  Второе значение `dj.int_g` (≈ 10 % награды + случайная добавка, для типа 8 ×0,5) — смысл не выяснен.
- **Расстояние между системами** (`cr.a`): `floor(sqrt(Σ Δ²))` по `pos`, z делится на 10, × 18,85.
- **Выбор станции назначения:** 20 % — станция агента, иначе 40 % — станция текущей системы, иначе случайная 0–99; не из уже предложенных, система должна быть открыта и иметь соседей (или быть текущей).
- Поле `extra_a` в `systems.json` — это **соседние системы** (переходы); переименовано в `neighbors`. У двух систем списка нет (закрытые).
- Не выяснено: смысл `cf.t`, `dj.int_g`, роли агентов кроме 5 и 7.
